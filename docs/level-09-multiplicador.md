# Nivel 9 — Multiplicador de equipo 🔴

> **Objetivo:** Mentoría y workflows para equipos. El rol de "engineering multiplier".
>
> **Dificultad:** Experto | **Proyectos:** 3 | **Tiempo estimado:** 6-8 horas

## Skills que ganarás

- [ ] Mentoría en AI-driven development
- [ ] Documentación de onboarding con IA
- [ ] Diseño de workshops
- [ ] Definición de métricas de impacto
- [ ] Team enablement

---

## Proyecto 1: Onboarding doc con IA

**Descripción:** Crea documentación de onboarding generada y mantenida por IA.

### Pasos

1. Diseña la estructura del onboarding doc
2. Usa Copilot para generar cada sección:
   - Setup del entorno
   - Arquitectura del proyecto
   - Convenciones de código
   - Cómo usar AI workflows del equipo
   - FAQ
3. Crea un proceso para mantener la doc actualizada con IA
4. Documenta cómo un nuevo engineer debería usarla

### Criterios de completitud

- [ ] Onboarding doc completa
- [ ] Proceso de actualización con IA definido
- [ ] Incluye sección de "AI workflows del equipo"
- [ ] Probado: alguien podría seguirla sin ayuda

---

## Proyecto 2: Workshop "AI-Driven Development"

**Descripción:** Diseña un workshop de 1 hora para enseñar AI-driven development.

### Estructura

```
0:00-0:10 — Intro: qué es AI-driven development
0:10-0:25 — Demo en vivo: construir un endpoint con IA
0:25-0:40 — Ejercicio práctico: attendees construyen algo
0:40-0:50 — Best practices y anti-patterns
0:50-1:00 — Q&A y recursos
```

### Pasos

1. Crea los slides con Copilot
2. Prepara la demo paso a paso
3. Diseña el ejercicio práctico (con solución)
4. Crea un handout con recursos y links
5. Documenta learning objectives

### Criterios de completitud

- [ ] Slides creados
- [ ] Demo rehearsed y documentada
- [ ] Ejercicio práctico con solución
- [ ] Handout con recursos
- [ ] Learning objectives definidos

## Proyecto 3: Métricas de productividad

**Descripción:** Define KPIs para medir el impacto de IA en el equipo.

### Métricas a definir

- Velocity (story points/sprint) antes vs después de IA
- Code quality (bugs por release, test coverage)
- Time to onboard new engineers
- PR review time
- Defect escape rate

### Pasos

1. Diseña el dashboard de métricas
2. Crea un script que recolecte datos de GitHub (PRs, issues, commits)
3. Genera visualizaciones
4. Documenta cómo interpretar las métricas
5. Define benchmarks de "what good looks like"

### Criterios de completitud

- [ ] 5+ KPIs definidos
- [ ] Script de recolección funcional
- [ ] Dashboard o reporte generado
- [ ] Documentación de interpretación
- [ ] Benchmarks definidos
